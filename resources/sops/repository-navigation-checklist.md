# 仓库目录查找顺序指南

一句话原则：

**目录名不通用，但查找顺序通用。**

不同项目的目录命名可能不一样，但找资料、找原型、找实际页面的顺序通常是稳定的。以后进入一个新仓库，可以先按下面顺序判断。

## 推荐查找顺序

### 1. 先看 README.md

README 通常会说明：

- 项目入口
- 目录结构
- 启动方式
- 主要模块
- 文档或原型的位置

如果不确定从哪里开始，先看 README。

### 2. 再找 docs/

`docs/` 通常存放产品和项目说明，例如：

- 产品说明
- 需求文档
- 原型说明
- 业务流程
- 设计记录
- 决策记录

如果目标是看产品逻辑、功能范围、流程设计，优先找这里。

### 3. 搜关键词

当目录不明显时，直接搜关键词更快。

常用关键词：

- `prototype`
- `原型`
- `design`
- `mock`
- `demo`
- `v2`
- 页面名称
- 功能名称

这一步适合快速定位隐藏在深层目录里的原型、页面或说明文档。

### 4. 找 apps/ 或 frontend/web/client

这些目录通常是真正能运行的前端页面所在位置，例如：

- `apps/`
- `web/`
- `frontend/`
- `client/`

如果目标是看实际页面、启动项目、验证交互，重点找这些目录。

### 5. 找 public/

`public/` 常见内容包括：

- HTML 原型
- 图片
- 视频
- 字体
- 静态资源
- 可直接访问的演示文件

如果要找静态原型或素材，可以重点检查这里。

### 6. 找 src/pages、src/components

如果要看页面是怎么实现的，一般继续深入到：

- `src/pages`
- `src/components`
- `src/views`
- `src/routes`

其中：

- `pages` / `views` 通常对应页面级结构
- `components` 通常对应页面里的组件细节
- `routes` 通常能帮助判断页面入口和访问路径

## 最实用的判断

**看产品原型：先找 `docs / design / prototype`。**

**看实际页面：找 `apps / web / frontend / client`。**

**看页面细节：找 `src / pages / components`。**

## 使用建议

进入新项目时，不要一开始就陷进代码细节。可以先按这个顺序建立地图：

1. README 确认项目整体入口
2. docs/design/prototype 确认产品和原型
3. apps/web/frontend/client 确认可运行前端
4. public 确认静态资源
5. src/pages/components 确认页面实现细节

这样可以先判断“资料在哪里、页面在哪里、实现在哪里”，再决定下一步深入查看。
